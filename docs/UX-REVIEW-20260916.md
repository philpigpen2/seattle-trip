# philiplaney.com user review — 16 September 2026

Scope: public entrance, sign-in, authenticated app library, app discovery and return to arcade. Public login was observed live in Chrome. The existing authenticated layout was reviewed from the exact current source in an isolated local render while a real login remained pending.

## Findings and response

1. **Sign-in is hard to read.** The live modal displays dark headings and field labels on a dark card, plus light button text on pale yellow. The app's Clerk appearance config uses outdated names. Use current foreground/input tokens and explicit dark primary-button text; bring dedicated auth routes into the same visual language.
2. **The app library has no useful hierarchy.** Ten equal-sized rows sit in a narrow 448px column on a wide desktop. A large arcade header pushes useful content down. Group apps by purpose in a responsive list, remove arbitrary emphasis on Dryht, and provide a compact brand/account header.
3. **Finding a particular app requires scanning everything.** Add labeled search, category filters, a visible count, and a clear action that recovers from empty results. Use legible Geist typography, descriptive app copy, generous targets, and keyboard focus indicators.
4. **Signing in makes the arcade inaccessible.** Add a separate arcade route and a clear return to the app library. Preserve every game and the existing input engine.
5. **One app is a dead end.** Both HEAD and GET of https://sinvitation.philiplaney.com returned 404 with DEPLOYMENT_NOT_FOUND. Vercel could not resolve that domain to a deployment. Retain the catalogue item but label it unavailable and do not make it a broken navigation link. Other eight checked destinations return 200 or expected authentication redirects; Dryht is unchanged.
